# M9 加权介数 GUI 集成验收

Windows Release 包中的 `PAGANI.exe` 已启用加权介数。选择 Weighted，在 Nodal Metrics 勾选 Betweenness centrality，然后选 Auto、CPU、GPU 或 Calibrate CPU + GPU。Default threads 优先读取 `PAGANI_THREADS`，未设置时使用最多 32 个线程。运行目录为 `build-m9-cuda/package/`，Qt 运行库及 Windows 平台插件已随程序部署。

## 混合批次

从 Qt 流程生成器导出批处理并直接执行。同一目录放入历史真实被试的两份 CSR，使用原有 4 mm 掩模、0.2 掩模阈值和 32 线程。输入各有 19,574 个节点。运行环境为 Windows、Qt 5.15.2、CUDA 12.6.2 和 RTX 3080 Ti。

| 输入密度 | 无向边数 | 孤立节点 | 自动后端 | 工具报告的读入至写出耗时 | 对历史 CPU 结果的最大绝对误差 |
|---|---:|---:|---|---:|---:|
| 0.05% | 95,780 | 13,222 | CPU，缺少匹配的加速记录 | 1.11 秒 | 0 |
| 0.50% | 957,805 | 4,420 | GPU，匹配本机实测配置 | 17.57 秒 | 0 |

日志中每张图各出现一次计算和一次后端选择。两个 `_bc.nm` 与各自历史 CPU 输出逐字节一致，随后 ConvertNII 生成两张结果图，逐体素核验了掩模内的全部节点。计时用于记录这一批次的执行过程。跨后端性能比较见[真实被试基准](M9_REALDATA_BACKEND.md)。

## 策略和故障处理

- Auto 在实际处理 CSR 时决定后端，所以同批新建的不同密度网络可以走不同后端。内置 GPU 建议仅覆盖原基准的 CPU 型号、线程数、GPU 型号、Windows 驱动、节点规模、边数及孤立节点范围，并要求显存支持完整源点批量。
- 其他配置可显式执行 Calibrate CPU + GPU。两种算法都完成且逐节点满足绝对容差 1e-8 和相对容差 1e-6 后，才保存校准选择并写一份结果。GPU 达到 1.10 倍耗时比时优先 GPU。校准以当前机器上的一次配对为依据，含设备探测与算法计算，不含共享的 CSR 读写。
- Auto 优先复用相同硬件、驱动、算法版本、CPU 线程数、节点数、边数、孤立比例档和源点批量的本地记录。缺少匹配时按内置建议或 CPU 执行。强制 GPU 遇到设备错误会报告失败。
- 对真实 0.50% 图用项目的显存限制开关模拟可用显存不足，Auto 在进入 GPU 内核前改走 CPU，结果哈希与上表一致。输入或数值异常会终止该步骤。节点文件关闭成功后再原子替换旧文件。

## 测试记录

Qt 控件测试覆盖切换有权/无权时勾选状态和后端选择的保留。流程测试检查命令、设置和批处理往返。GPU 专项和建网后端到端用例 4 项通过，M9 原有 CPU/GPU 数值配对 18 项通过。标准回归 111 项通过、25 项按配置跳过。本轮平台验证覆盖本机 Windows。

本机 `tests/_work/m9_gui/` 保存 `mixed.bat`、`mixed.log`、`mixed-results.json`、`memory-fallback.log`、数值配对结果及 JUnit XML。真实混合批次可在项目根目录运行 `python tests/_work/m9_gui/check_mixed.py` 复核，需要沿用该目录对应的原始 CSR 和掩模，以及测试程序使用的 Qt 运行环境。
