# M9 加权介数中心性 GPU 验收

2026-11-20，在 Windows x64、NVIDIA GeForce RTX 3080 Ti 12 GiB、驱动 621.14 上实测。使用与 Windows CI 相同的 CUDA Toolkit 12.6.2，nvcc 12.6.77、MSVC 19.34、CMake 3.24、Ninja 和 Release 配置。本地构建为实测显卡生成 SM 8.6 机器码。工具链位置为 `build-toolchains/cuda-12.6.2`，本地程序位于 `build-m9-cuda/package/exefiles_weighted/`，其中 `CUBC` 运行 CPU 参考算法，`CUBC_GPU` 运行 CUDA 算法。

## 算法与验收口径

每个线程块负责一个源点，同时处理的源点数受可用显存约束。GPU 在双精度下迭代松弛距离直至收敛，再沿严格递增的最短路径有向无环图分层累积路径数和逆向依赖值。路径数在对数域累加，分批结果按固定的源点顺序相加。CPU 和 GPU 共用权重验证与边长转换，并采用相同的 1e-12 相对容差。平均度达到 32 时，同一 warp 的线程协作读取一行 CSR。

CPU、GPU 先后读取同一个 CSR，分别生成 float32 节点结果。每次运行前清理该用例的旧输出。数值比较逐节点进行，允许相对误差 1e-6 和绝对误差 1e-8。异常输入检查两端的退出状态、错误内容和输出文件。BCT 五组期望值取自先前 MATLAB R2026a 验证保存的固定参考数据。近等长的两个用例单独检验项目规定的相对容差。

## 19,574 节点性能

固定种子 44 生成无向随机图，连边概率 1%，种子 65 从 [0.1, 1) 独立生成边权。实际 1,911,913 条无向边，密度为 0.9981%。CPU 使用 32 个线程。复用逐字节校验过的同一 CSR，CPU 和两次最终 GPU 运行的输出 SHA-256 相同。GPU 中位耗时为 67.46 秒，相对 CPU 的加速比为 1.23 倍。该固定合成图上的两次 GPU 墙钟时间均低于两分钟。

| 后端与轮次 | 命令行耗时（秒） | 算法缓冲区峰值（MiB） | 整卡采样起点（GiB） | 整卡采样峰值（GiB） |
|---|---:|---:|---:|---:|

| GPU，第 1 次 | 67.72 | 306.82 | 9.66 | 10.29 |

整卡读数来自 NVML，采样线程在两次查询之间等待 25 ms，包含桌面、驱动及其他进程的占用。缓冲区峰值由内核启动前所有同时存活的 CUDA 分配大小合计。两种数值分别用于评估设备整体占用和算法显存需求。首轮实现的两次 GPU 耗时为 111.25 和 113.24 秒。

标准 Windows 回归另有 109 项通过，25 项按配置跳过。专项 CUDA 比对在实卡上独立执行。

## 复测与原始记录

在项目根目录设置 `PAGANI_BIN` 为 CUDA 构建的 `package` 绝对路径、`PYTHONPATH` 为项目 `tests` 绝对路径，然后运行以下命令。

```powershell
python -m pytest -q -p weighted_bc_parity tests/test_weighted_betweenness.py --bc-report parity.json --junitxml parity.xml
```

本机 `tests/_work/m9_gpu/` 保存 `parity.json`、`parity.xml`、`dense-and-unweighted.xml`、`toolchain.json`、`build-final.log` 以及两组性能实测的脚本。`seed65-n19574/benchmark-final.json` 包含最终 GPU 轮次、CPU 参考耗时、输入与输出哈希及 NVML 采样数。本机全量构建使用串行链接，避免历史程序的同名导入库发生写入冲突。构建可在项目根目录通过 `./build-m9-cuda/rebuild.ps1` 复现。
